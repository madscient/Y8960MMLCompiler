## 目的と範囲

MML を書いたテキストファイルから、**Y8960 BASIC Extension の `MSAVE` が
書き出すのと同じ Y8SQ ブロック**と、**`EXPORT PCM` が書き出すのと同じ Y8PC
ファイル**を作るクロスコンパイラ。Windows / Linux / macOS。

- MML の仕様は Y8960 BASIC Extension と互換
- 出力の仕様は `Y8960BasicExtension/doc/bytecode.md` と `doc/pcmfile.md`
- **再生は範囲外。** 鳴らすのは Y8960Sequencer（`../Y8960Sequencer`）

## 決定事項

### 開発言語は C++、ビルドは CMake

- 利用者の決定（2026-09-18）
- Y8960Sequencer と同じ組み合わせ。C++17、CMake 3.20 以上

### 3層に分ける

| 層 | 中身 | 依存してよいもの |
|---|---|---|
| コア | ソースの読み込み、MML の解析、バイトコード生成、Y8SQ / Y8PC の書き出し | 標準ライブラリだけ |
| CLI | 引数の解釈、ファイル入出力、診断の表示 | コア |
| GUI | 画面 | コア |

- Y8960Sequencer と同じ分け方
- **前提**: GUI のツールキットを替えても、作り直すのは GUI 層だけで済むこと

### GUI は後回しにする。CLI を先に完成させる

- 利用者の決定（2026-09-18）。ツールキットは GUI に着手するときに決める
- **層は先に切っておく**ので、決定を遅らせても値段は上がらない

### コマンド名は `y8mmlc`、第1引数が MML ソース

```
y8mmlc <MML ソース> [-o <基底名>] [--out-dir <フォルダ>]
```

- コマンド名は要件で与えられている
- ソースは UTF-8。BOM は付いていても読む

### 出力は MSX-DOS の 8.3 に合わせ、`.SQ` と `.PC` にする

- 利用者の決定（2026-09-18）
- `song.mml` → `SONG.SQ`（Y8SQ）と `SONG.PC`（Y8PC）
- 基底名は入力の茎を大文字にしたもの。**8文字を超えるときは切り詰めて警告を
  出す** ―― 黙って切ると、別の曲が同じ名前になったことに気づけない
- `-o` は基底名を取る。拡張子を書いても捨てる。ここでも8文字を超えれば警告
- **`.PC` は `#pcm` を書いたソースにだけ出る。** ADPCM を使わない曲に空の
  ファイルを作らない
- **前提**: 出力を MSX へ持っていく経路が、名前をそのまま使えること。PC 上で
  だけ扱うなら長い名前のほうが読みやすいが、持ち込みのたびに改名するほうが高い

### MML ソースの形式

詳細は [`mml-source.md`](mml-source.md) が正。ここには**なぜそうしたか**だけ置く。

#### 1ファイル ＝ 1シーケンス

- Y8SQ ブロックはシーケンス1本ぶんの形（`bytecode.md`「ブロック」）で、
  `MSAVE` もシーケンス1本を書き出す。トラック名 `A`-`P` が 16 トラックに
  ちょうど対応する
- シーケンス番号を書く場所を作らないので、**メタコマンドにシーケンスの概念が
  出てこない**

#### トラック行は同じトラック名を何行でも書ける。連結される

- ROM の `MTRK` を分けて呼ぶのと同じ
- **ただしループ・ブロック・連符が閉じる単位はファイル全体**にした。ROM は
  `MTRK` 1回の中で閉じることを求めるが、そちらは「まだ書かれていない `MTRK`」
  を指せないという BASIC 側の都合で、ファイルにはその都合が無い
- **流用元との差。** ROM で通るものは通り、ROM で落ちるものが通る側の差なので、
  同じソースが同じバイト列になる関係は保たれる

#### 変数参照 `=x;` `Xx;` は、ファイル内のマクロとして再解釈する

- 利用者の決定（2026-09-18）。PC 側に BASIC の変数は無い
- `#define <名前> <数値>` を `=名前;` が、`#define <名前> "<MML>"` を
  `X名前;` が参照する
- **連鎖は 8 本まで**（ROM の `XCHAIN_MAX` と同じ）。自分を指す定義で
  終わらなくなるのを止めるため
- **流用元との差2つ。** どちらも ROM で落ちるものが通る側
  - **`X名前;` の後にも MML を書ける。** ROM が禁じているのは、変数の文字列を
    読み終わったあと元の位置へ戻る手段を持たないため。ファイルなら戻れる
  - **名前は英字で始まる英数字と `_`。** BASIC の変数名の規則に縛られない

#### ADPCM は `#pcm` と `#voice` で結び付ける

- 利用者の決定（2026-09-18）
- `#pcm <JSON のパス>` が adpcm_packer の出力（`.json` と、同じ茎の `.bin`）を
  指し、`#voice <番号 0-31> <エントリ名>` が JSON の `entries[].name` を
  ボイスファイル番号に写す
- **曲とサンプルの対応が MML ソースの中で閉じる。** ビルドのコマンドに覚えて
  おくことが無くなる
- **番号を entry の並び順に振らない理由。** サンプルを1つ足しただけで以降の
  番号が全部ずれ、曲のほうを直すことになる

### プリセット音色表はソースに同梱し、出所を明記する

- 利用者の決定（2026-09-18）
- **同梱が要る理由。** `bytecode.md` は「レコードのある音色はシーケンスが自分で
  持つ」と定めている。`@0`-`@63` を書いた時点で、コンパイラが 32 バイト×64 本の
  実体を持っていないと Y8SQ が作れない。読み込む側（Y8960Sequencer）はこの表を
  持たない設計になっているので、**持つ側はこちらしかない**
- **確認済み**（`../Y8960BasicExtension/src/tab/voicedat.asm` の冒頭コメントと
  同リポジトリ `README.md` の「権利」節を読んだ）。表は日本楽器製造株式会社
  （YAMAHA）および株式会社アスキーの著作物のフォークで、Y8960BasicExtension は
  公開リポジトリに出典明記のうえ同梱している。同じ扱いを採る
- **SCC のプリセット波形**（`src/tab/wavedat.asm`）は Y8960BasicExtension が
  生成したもので、出典の制約は無い
- **OPL2EX のリズム音色3本**（索引 32-34）は出典が別で、CC BY-SA。
  **再配布時に出典明記が条件**なので、`README.md` の「権利」節に書く
- **写しは手で打たない。** `tools/gen_voicedata.py` が ROM の `voicedat.asm` と
  `wavedat.asm` から `src/core/voicedata.cpp` を作る。ROM 側の表が動いたら
  走らせ直す
- 値段: 同梱をやめるなら、表を外部データファイルにして実行時に読む形に変える。
  **表の中身を持つ翻訳単位1本と、その読み込み口だけが動く**

### バイトコードの仕様は `bytecode.md` が正。ROM のコードは隅を決めるときだけ読む

- **仕様とコードが食い違うときは仕様に合わせる。** Y8960Sequencer と同じ方針
  （向こうの `doc/plan.md`）。ROM 側は不具合として直っている
- 仕様が名前を付けていない隅（音長の端数、付点の重ね方、連符の割り前）は
  ROM のコードを読んで合わせる。**読んだ箇所と読み取った規則をここに記録する**

#### 読み取った規則

**確認済み**（`../Y8960BasicExtension/src/mml/lexer.asm` の `GETLEN` /
`GETLENDOT` / `GETLENDEF`、`src/mml/parse.asm` の `CM_LENGTH` /
`CM_TUPSTART` を読んだ。**走らせてはいない**）。

- **音長の tick は `192 / n` の切り捨て。** 端数の繰り越しは無い。MsxMusic の
  MML が持つ「端数は次の音符へ繰り越される」は、この ROM には入っていない
- **付点は、基準を `d` として `d >>= 1; 合計 += d` を付点の数だけ繰り返す。**
  `R4.` は 48 ＋ 24 ＝ 72。`n` が小さいと `d` が 0 になり、それ以上は増えない
- **連符の割り前は `GETLEN` の結果を音符の数で割った切り捨て。** 割り前が
  2 tick 未満なら `Illegal function call`（`音符数 × n > 96` と同じ条件）
- **連符長にも付点を書ける**（`{CDE}4.`）。ROM が `GETLEN` をそのまま使った結果
- **数えるのは音符の文字と `N`*n* と `R`*n* だけ。** `&` と `@W`*n* は時間を
  取るが数に入らない

**確認済み**（`../Y8960BasicExtension/doc/plan.md` 段階6 が持つ、フォークの
openMSX で取った実例を読んだ。**こちらで走らせてはいない**）。回帰試験の
期待値にそのまま使う。

| MML | バイト列 |
|---|---|
| `L8CDE` | `00 18 02 18 04 18 FF` |
| `{CDE}4` | `00 10 02 10 04 10 FF` |
| `{C8DE}4` | `00 18 02 10 04 10 FF` |

- **`T120@1V15O3Q4A1` の実例（`84 78 82 01 …`）は段階6 のもので、そのままでは
  使えない。** 段階14 で FM の `@1` は `85` ＋ 音色集合の索引になった。
  `84 78`・`81 7F`・`80 03`・`83 04`・`09 80 C0` の部分は変わっていない

#### ROM のコードが仕様と食い違っていた箇所

**方針どおり仕様に合わせた。** どれもこちらが ROM より厳しい側に倒れるので、ROM が受け付ける MML の一部をこちらが断る。**未検証** ―― ROM を
走らせて確かめたわけではなく、コードを読んで気づいたもの。

- **`(TC)` が2つ以上あって `(CODA)` が1つも無いトラック。** ROM は待ち行列を
  排出する場所（`PARCODA`）を通らないので、2つ目以降の飛び先に**鎖のリンク
  （直前のフィールドの位置）が残る**。仕様は「0 なら無視」なので、こちらは
  全部 0 を書く（`../Y8960BasicExtension/src/mml/loop.asm` の `PARTC` と
  `PARCODA`、`src/inc/memmap.inc` の `CMPL_CODA`）
- **長さ 0 の `N`*n* が2つ続く形。** ROM の `CM_NOTEABS` は `CMPF_NOTIME` を
  見ない（`NOTEMIT` だけが見る）ので通ってしまう。仕様は「長さ 0 の音符のあと、
  次の音符までに時間を進めるものを挟まないと `Illegal function call`」なので、
  こちらは `N`*n* でも断る（`src/mml/parse.asm` の `CM_NOTEABS`）
- **ADPCM チャンネルの `@`*n* が 32 以上。** ROM の `CHKVOICE` は FM 系の範囲
  （0-191）で見るだけで、ADPCM かどうかを知らない。仕様は 0-31 なので、
  こちらは 32 以上を断る（`src/mml/parse.asm` の `CHKVOICE` と `VOIKIND`）

**ROM 側へ返すかどうかは決めていない。** 返すなら
`../Y8960Sequencer/doc/rom-feedback.md` と同じ形になる。

### JSON は自前で読む

adpcm_packer の JSON を読むのに nlohmann/json を FetchContent で取る案があったが、
**コアは標準ライブラリだけに依存する**という決定のほうを採った
（`src/core/json.cpp`、約250行）。

- 設定時にネットワークが要らない。オフラインでビルドできる
- 読むのは1つのスキーマだけで、そこに要る JSON は全部揃っている
- 値段: 入力の形が増えたらこちらが直す。**JSON の仕様のうち使っていないのは、
  サロゲートペアを1つの符号位置に畳むことだけ**（名前に絵文字を書くと壊れる）

### 診断は行と桁を持ち、1回の実行で出せるだけ出す

- ROM は `Illegal function call` の1種類しか返せないが、**PC にはその制約が
  無い。** どこが悪いかを言えるなら言う
- **最初の1件で止めない。** トラックごとに解析するので、あるトラックの誤りは
  他のトラックの解析を妨げない
- **前提**: 診断の文言は外に出る値だが、**振り直しても波及しない**（文言だけが
  動く）。だから着手前に決めない

## 見送った案

### ROM の Z80 コードを走らせて MML をコンパイルする

`MTRK` をエミュレータの中で呼び、`MSAVE` の結果を取り出す案。ROM と同じ
バイト列になることが構造上保証される。

見送った理由:
- MSX エミュレータと ROM イメージの配布が要る。ROM には他の拡張BASIC と、
  出典の違う音色データが含まれる
- 要件はマルチプラットフォームのコマンドライン／GUI ツールで、そこに MSX の
  エミュレータを抱えることになる
- Y8960Sequencer が同じ理由で同じ案を見送っている

### ADPCM のエンコードもこのツールで行う

要件は「adpcm_packer が出力したダンプと JSON」を入力に取ると定めている。
**符号化は adpcm_packer の仕事**で、こちらはその出力を Y8PC の形に詰め替える。

## 未決事項

### 外から見える値（まだ決めていない）

- **`@128`-`@191`（`VOICE COPY` で作る音色）と `@16`-`@31`（`WAVE COPY` で作る
  SCC 波形）をどう与えるか。** BASIC 側はプログラムが作るもので、MML ソースには
  それに当たるものが無い。**いまは「未対応」のエラーにする** ―― 黙って通すと、
  レコードの無い索引を指すブロックができる
  - 足すなら音色定義のメタコマンド（`#voicedef` のようなもの）になる。
    値段: メタコマンド1つ、音色集合への登録経路は既にあるので、
    **解析と文書1本**で足りる
- **リピート回数・tick の分解能など、ブロックの外にある値。** Y8SQ ブロックは
  それらを持たない（演奏を始める側が決める）ので、コンパイラの出力にも入らない。
  入れる場所を作るなら、読み飛ばしてよいチャンク `80`-`FF` になる
- 複数の MML ソースを1回で処理する形（ワイルドカード、リスト）を持つか

### 検証をどこまでやるか

**いちばん強い検証は、同じ MML を ROM と このコンパイラの両方に通して
バイト列を突き合わせること。** ROM 側は openMSX のフォークでしか回せないので、
このリポジトリからは回せない。いまの代わりは2つ。

- ROM の `doc/plan.md` が持つ実例を期待値に写した回帰試験（`tests/mml_test.cpp`
  の「ROM:」と書いてある行）。**写した実例は上の表が持つ**
- **出力を Y8960Sequencer に読ませる。** 向こうは同じ仕様から独立に書かれた
  読み手なので、こちらの書き手の取り違えを捕まえる見込みがある

足すなら、ROM 側に「MML を食わせて `MSAVE` の結果を吐く」試験スクリプトを
置いてもらい、その出力をこちらの試験データにする。

**この検証を見送っている間、互換性の根拠は「仕様文書と ROM のコードを読んで
実装し、独立の読み手が受理した」までである。** ROM と同じ音が鳴ることは
確かめていない。`README.md` には書かない（利用者向けの文書に開発の都合は
書かない）代わりにここに書く。
