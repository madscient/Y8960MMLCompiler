# MML ソースファイル

**この文書は、`y8mmlc` が読む MML ソースファイルの書き方。**

MML そのもののコマンドは [`mml-reference.md`](mml-reference.md) にある。
この文書が定めるのは、**その MML をテキストファイルに並べる形** ―― どの行が
どのトラックのものか、トラックをどの音源に割り当てるか、音色や ADPCM の
サンプルをどう用意するか。

## ファイル全体の形

UTF-8 のテキストファイル。**行の種類は3つだけ**で、行の先頭の文字で決まる。

| 行の先頭 | 種類 |
|---|---|
| `#` | メタコマンド |
| `A`-`P` ＋ 空白 | トラック行 |
| `;` | コメント |

空行と、空白だけの行は読み飛ばされる。**このどれにも当たらない行はエラー。**

**行の末尾が `\` なら、改行を捨てて次の行がそこに続く。** 長いメタコマンドや
長い MML を読みやすく折り返せる。行の種類を見るのはつなげた後なので、
**コメント行を `\` で終えると次の行もコメントになる。**

```
A  O4 L8 cdefgab>c \
         >cbagfedc<
```

```
; ---- 例 ----
#assign A OPL2EX1 0
#assign B OPL2EX1 1
#assign C SSGS 0

#define TEMPO 140

A  T=TEMPO; @0 V13 L8 O4 cdefgab>c
B  T=TEMPO; @0 V10 L2 O3 c   g
C  @0 V12 L8 O5 |: ceg> c< :|4
```

**コメントは行の先頭にだけ置ける。** 行の途中から後ろをコメントにする書き方は
無い ―― MML は `=x;` と `Xx;` で `;` を使う。

**1つのファイルがシーケンス1本**（16 トラック）を表す。トラック名 `A`-`P` が
トラック番号 0-15 にあたる。

## トラック行

トラック名、空白、そのトラックの MML。

```
A  O4 L8 cdefgab>c
```

- **同じトラック名を何行書いてもよい。** 上から順につながる。長い曲を
  読みやすく切って書ける
- 行の終わりで MML が途切れていてよい。**次の同じトラックの行へそのまま続く**
- トラック名は大文字の `A` から `P`。トラック名の後には空白が要る
- **MML は大文字小文字を問わない。** `CDE` と `cde` は同じ

**そのトラックに `#assign` が無いとエラー。** どの音源に向けた MML かが
決まらないと、書き出す形が決まらない。

## メタコマンド

`#` の直後にコマンド名。名前は大文字小文字を問わない。引数は空白で区切る。

### `#assign` ―― トラックを音源に割り当てる

```
#assign <トラック名> <デバイス> <チャンネル>
```

デバイスは番号でもシンボルでも書ける。チャンネルは 0 から数える。

| 番号 | シンボル | チャンネル | 内容 |
|--:|---|---|---|
| 0 | `SSGS` | 0-5 | |
| 1 | `OPLLEX1` | 0-8, 10 | 0-8 FM ／ 10 リズム |
| 2 | `OPLLEX2` | 0-8, 10 | 同上 |
| 3 | `OPL2EX1` | 0-10 | 0-8 FM ／ 9 ADPCM ／ 10 リズム |
| 4 | `OPL2EX2` | 0-10 | 同上 |
| 5 | `DCSG1` | 0-3 | 0-2 矩形波 ／ 3 ノイズ |
| 6 | `DCSG2` | 0-3 | 同上 |
| 7 | `SCC` | 0-4 | |

```
#assign A OPL2EX1 0
; 番号で書いても同じ
#assign B 3 1
```

- **同じデバイスの同じチャンネルを2つのトラックに割り当てるとエラー。**
  1つのチャンネルを鳴らせるのは1トラックだけ
- **1つのブロックで、チャンネル 10 と 6-8 は同時に使えない。** チャンネル 10 は
  リズム音で、鳴らすあいだチャンネル 6-8 を使う
- **`#assign` を書いて MML を1行も書かないトラックも、割り当てごと出力に入る。**
  まだ書いていないパートの割り当てが残る

割り当てたチャンネルによって、そのトラックの MML の書き方が変わる。

| チャンネル | 書き方 |
|---|---|
| OPL2EX の 9 | ADPCM 用 MML |
| OPLLEX・OPL2EX の 10 | リズム音用 MML |
| それ以外 | ふつうの MML |

### `#define` ―― 名前を付ける

```
#define <名前> <数値>
#define <名前> "<MML>"
```

MML の中から `=名前;` と `X名前;` で参照する。

```
#define TEMPO 140
#define RIFF  "cdefgab>c"

A  T=TEMPO; L8 XRIFF; XRIFF;
```

- **`=名前;` は数値**。MML で数を書くところならどこでも使える
- **`X名前;` は MML**。その場に展開される
- 名前は英字で始まり、英数字と `_` が続く。大文字小文字を区別する
- **`X名前;` でつなげるのは 8 段まで。** 定義が自分を指すと終わらないため
- 同じ名前を2度定義するとエラー

### `#voice` ―― FM 音色を作る

```
#voice <形式> @<番号 128-191> <値>
```

自分で作る FM 音色。MML の `@`*n* がその番号で選ぶ。**`@0`-`@63` の
プリセットはコンパイラが持っているので、ここには書かない**
（一覧は [`mml-reference.md`](mml-reference.md) の付録）。

形式は値の書き方を選ぶ（下記「形式」）。番号には MML と同じ `@` を付ける。

値はカンマで区切り、合わせてちょうどその形式の数だけ書く。

- 数値は10進か `$` ＋16進。**10進は -128 から 255**（負の数はそのまま
  1バイトになる）
- `"..."` と書くと、その文字がそのままバイトになる。音色名を読める形で
  書ける
- 数がちょうどでなければエラー

```
#voice AUDIO @128 "Piano 1 ", \
                  $00,$00,$0A,$00,$00,$00,$00,$00, \
                  $31,$0E,$D9,$11,$30,$00,$00,$00, \
                  $11,$00,$B2,$F4,$70,$00,$00,$00
```

#### 形式

| 形式 | 値の数 | 中身 | 使える音源 |
|---|--:|---|---|
| `AUDIO` | 32 | MSX-AUDIO・MSX-MUSIC の拡張BASIC の音色データ | OPLLEX・OPL2EX |
| `OPL` | 12 | OPLLEX・OPL2EX のレジスタの値を詰めたもの | OPLLEX・OPL2EX |
| `SFG` | 40 | SFG の拡張BASIC の音色本体 | 無い |
| `MAKOTO` | 50 | Makoto の拡張BASIC の音色配列 | 無い |
| `OPM` | 32 | OPM・OPNA・OPNB のレジスタの値を詰めたもの | 無い |
| `OPL3` | 24 | OPL3 の 4 オペレータの音色 | 無い |

- 形式の名前は大文字でも小文字でもよい
- **シーケンスデータに入るのはレジスタの値を詰めた形。** `AUDIO` は `OPL` に、
  `SFG` と `MAKOTO` は `OPM` に詰めて入る。`OPL`・`OPM`・`OPL3` は書いたものが
  そのまま入る
- **形式は音源ではなく、書き方を選ぶ。** `AUDIO` と `OPL` の音色は、OPLLEX でも
  OPL2EX でも使える
- `SFG`・`MAKOTO`・`OPM`・`OPL3` は Y8960 に無い音源のための形式で、定義はできるが、
  どのトラックで `@`*n* に選んでもエラーになる

#### 形式 `AUDIO`

MSX-MUSIC と MSX-AUDIO の拡張BASIC の音色データ（`VOICE COPY` が扱う 32 バイト）と
同じ形で、上の例の1行目（オフセット 0〜15）が音色全体の設定、2行目がモジュレータ、
3行目がキャリア。2つのオペレータは同じ並び。

| オフセット | 内容 |
|--:|---|
| 0〜7 | 音色名（8文字） |
| 8〜9 | 移調。9 が半音の数（符号付き）、8 がその端数（256 分の 1 半音） |
| 10 | bit0：アルゴリズム ／ bit3〜1：フィードバック ／ bit7〜4：MSX-AUDIO 用の設定 |
| 11〜15 | 予約（0 にしておく） |

| モジュレータ | キャリア | 内容 |
|--:|--:|---|
| 16 | 24 | bit3〜0：MULT ／ bit4：KSR ／ bit5：EG ／ bit6：PM ／ bit7：AM |
| 17 | 25 | bit5〜0：トータルレベル ／ bit7〜6：レベルキースケール |
| 18 | 26 | bit3〜0：ディケイレイト ／ bit7〜4：アタックレイト |
| 19 | 27 | bit3〜0：リリースレイト ／ bit7〜4：サステインレベル |
| 20 | 28 | ベロシティ（使わない） |
| 21 | 29 | bit1〜0：波形 |
| 22〜23 | 30〜31 | 予約（0 にしておく） |

**シーケンスデータに入るのは、鳴らすのに使う項目だけ。** 音色名、予約、
ベロシティ、バイト 10 の MSX-AUDIO 用の設定、波形の bit7〜2 は入らない。
移調は半音の単位に丸めて入る（端数が 128 以上なら切り上げ）。

**どの項目が効くかは音源で違う。**

- **OPLLEX** は MSX-MUSIC と同じ読み方をする。アルゴリズムとキャリアの
  トータルレベルは使わない。波形は bit0 だけで、0 が正弦波、1 が半波整流
- **OPL2EX** はバイト 10 のアルゴリズムとフィードバックを使う。波形は
  bit1〜0 の4種類
- 移調はどちらの音源でも効く

#### 形式 `OPL`

シーケンスデータに入る形そのもの。`AUDIO` と違って、書いたものがそのまま入る。

```
#voice OPL @128 $0A,$00, \
                $0E,$D9,$11,$31,$00, \
                $00,$B2,$F4,$11,$00
```

| オフセット | 内容 |
|--:|---|
| 0 | bit0：アルゴリズム ／ bit3〜1：フィードバック |
| 1 | 移調。半音の数（符号付き） |
| 2〜6 | モジュレータ |
| 7〜11 | キャリア |

| モジュレータ | キャリア | 内容 |
|--:|--:|---|
| 2 | 7 | bit5〜0：トータルレベル ／ bit7〜6：レベルキースケール |
| 3 | 8 | bit3〜0：ディケイレイト ／ bit7〜4：アタックレイト |
| 4 | 9 | bit3〜0：リリースレイト ／ bit7〜4：サステインレベル |
| 5 | 10 | bit3〜0：MULT ／ bit4：KSR ／ bit5：EG ／ bit6：PM ／ bit7：AM |
| 6 | 11 | bit2〜0：波形 |

使わないビットには 0 を書く。どの項目が効くかは `AUDIO` と同じで、
波形は OPLLEX が bit0、OPL2EX が bit1〜0 だけを使う。

#### 形式 `SFG` と `MAKOTO`

どちらも、それぞれの拡張BASIC の音色の形のまま書く。

- **`SFG`** は SFG の拡張BASIC が `CALL VOICE` と `VOICE COPY` で扱う 40 バイトの
  本体（音色名を除いたもの）
- **`MAKOTO`** は Makoto の拡張BASIC の 50 要素の音色配列（N88-BASIC(86) の形に
  SSG-EG と AMS を加えたもの）。要素1つを値1つとして、配列の並びのとおりに書く。
  デチューンの −3〜−1 は負の数で書ける

`OPM` に詰めるとき、音色ごとに持てないものは落ちる。

- `SFG`：LFO の速度・AMD・PMD・波形、出力先、オペレータごとのベロシティ感度・
  レベルキースケール・トータルレベルへの加算
- `MAKOTO`：LFO の項目と PM 感度（Makoto の拡張BASIC も読まない）

### `#wave` ―― SCC 波形を作る

```
#wave <番号 16-31> <32バイト>
```

`WAVE COPY` が作る波形にあたるもので、SCC のトラックの `@`*n* がその番号で
選ぶ。**`@0`-`@15` のプリセットはコンパイラが持っている。**

32 バイトはそのまま波形の振幅で、書き方は `#voice` と同じ。振幅は符号付き
なので10進の負の数で書ける。

```
#wave 16 -124,-116,-108,-100, -92, -84, -76, -68, \
          -60, -52, -44, -36, -28, -20, -12,  -4, \
            4,  12,  20,  28,  36,  44,  52,  60, \
           68,  76,  84,  92, 100, 108, 116, 124
```

### `#env` ―― ソフトウェアエンベロープを作る

```
#env <番号 1-31> <AR>,<DR>,<SL>,<RR>
```

`ENV COPY` が作るエンベロープにあたるもので、SSGS・SCC・DCSG のトラックの
`@E`*n* がその番号で選ぶ。動きと4つの値の意味は
[`mml-reference.md`](mml-reference.md) の「ソフトウェアエンベロープ」にある。

```
; AR 16, DR 20, SL 8, RR 10
#env 1 16,20,8,10
#assign A SSGS 0
A @E1 V15 L2 O4 C R1
```

| 値 | 意味 | 鳴り方が決まっている範囲 |
|---|---|---|
| AR | アタックの速さ | 0〜32 |
| DR | ディケイの速さ | 0〜32 |
| SL | サスティンの高さ | 0〜15 |
| RR | リリースの速さ | 0〜32 |

- 値は10進か `$hh` で、0〜255 を書ける。**範囲を超えた速さは 32、高さは 15 と
  して鳴る**
- **シーケンスに入るのは、SSGS・SCC・DCSG のトラックが `@E` で選んだ番号だけ。**
  作っただけで使わない番号は入らない
- 同じ番号を2度書くとエラー。`@E0` はエンベロープ無しなので、0 は作れない

### `#pcmbank` ―― ADPCM のサンプルを読む

```
#pcmbank <JSON か Y8PC のパス>
```

[adpcm_packer](https://github.com/madscient/adpcm_packer) が出した JSON か、
Y8PC ファイル（`.PC`）を指す。JSON なら**同じ茎の `.bin`**（ダンプ）が同じ
フォルダにあることが要る。

```
; drums.json と drums.bin を読む
#pcmbank drums.json
```

**バンクは自分で番号を付ける。** 並んでいるエントリが先頭から
ボイスファイル番号 0, 1, 2 … を取るので、**これだけで `@`*n* が鳴らせる。**

```
; entries が bassdrum, snare, hihat の順なら、そのまま 0, 1, 2 で鳴る
#pcmbank drums.json
#assign  D OPL2EX1 9
D  L8 @0 c @1 c @2 c
```

- パスは**この MML ソースからの相対**。絶対パスも書ける
- **1つのソースに1回だけ**
- 番号が付くのは**先頭の 64 個**まで。それより後ろのエントリは `#adpcm` で
  番号を付けないと鳴らせない
- JSON の `codec` は `adpcm-b`、`boundary` は `256` でなければエラー。
  Y8960 の ADPCM が読むのはこの形だけ
- サンプリング周波数は JSON の `sample_rate`。**1800-16000Hz の外はエラー**
- パスに空白は書けない

**Y8PC を指したときは、Y8PC が持つ番号をそのまま使う。** Y8PC は番号ごとの
設定を自分で持っているので、並び順で番号を付け直すことはしない。出力の
`.PC` は読んだ Y8PC と同じになる。Y8PC にはエントリの名前が無いので、
**`#adpcm` とは一緒に使えない。**

```
; y8mmlc が前に書き出した SONG.PC をそのまま使う
#pcmbank SONG.PC
#assign  D OPL2EX1 9
D  L8 @0 c @5 c
```

### `#adpcm` ―― 番号を名前で指定する

```
#adpcm <番号 0-63> <エントリ名>
```

`#pcmbank` が付けた番号のほかに、**名前で指したエントリをその番号にも置く。**
バンクにサンプルを足しても番号が動いてほしくないときに書く。

```
#pcmbank drums.json
#adpcm   10 bassdrum
#adpcm   11 snare

#assign D OPL2EX1 9
D  L8 @10 c @11 c @10 c @11 c
```

- `#pcmbank` より後に書く
- **既定の番号は消えない。** 上の例では bassdrum が 0 番でも 10 番でも鳴る
- **同じ番号を2度書くとエラー。** JSON に無い名前もエラー

## 出力

```
y8mmlc song.mml
```

| ファイル | 中身 |
|---|---|
| `SONG.SQ` | シーケンスデータ（Y8SQ） |
| `SONG.PC` | ADPCM のサンプルと設定（Y8PC） |

- 名前は入力の茎を大文字にしたもの。**MSX-DOS の 8.3 に収まるように、8文字を
  超える茎は切り詰められる**（そのとき警告が出る）
- **英数字以外の ASCII と、ASCII でない文字は `_` になる。** ASCII でない文字は
  1文字が `_` 1つになり、そのとき警告が出る（`曲1.mml` → `_1.SQ`）。`曲.mml` と
  `歌.mml` はどちらも `_.SQ` になるので、`-o` で名前を付けるとよい
- `-o <基底名>` で別の名前にできる
- `--out-dir <フォルダ>` で別の場所に置ける
- **`SONG.PC` は `#pcmbank` を書いたソースにだけ出る**

`.SQ` は Y8960 BASIC Extension の `CALL MLOAD` が読む形、`.PC` は
`CALL IMPORT PCM` が読む形。どちらも Y8960Sequencer がそのまま鳴らせる。

## Y8960 BASIC Extension と違うところ

MML のコマンドは同じ。**違うのは、BASIC の変数を使う2つのコマンド**だけ。

| | BASIC | このコンパイラ |
|---|---|---|
| `=x;` | 数値変数 `x` の値 | `#define` で付けた名前 |
| `Xx;` | 文字変数 `x` の MML | `#define` で付けた名前 |
| `Xx;` の後ろ | 何も書けない | 続けて書ける |

コマンドの意味は同じでも、**`#env` で作っていない番号を `@E` で選ぶとエラーに
なる。** BASIC では `ENV COPY` していない番号も選べるが、そのときの鳴り方は
保証されない。

ループ・ブロック・連符が閉じる単位も違う。**BASIC では `CALL MTRK` 1回の中で
閉じる必要があるが、ここではファイルの中で閉じていればよい。** `|:` を書いた
行と `:|` を書いた行が別でも通る。

## いまできないこと

**リピート回数と tick の分解能。** シーケンスデータはこれらを持たない ――
演奏を始める側（`CALL MSTART`、Y8960Sequencer）が決める。
